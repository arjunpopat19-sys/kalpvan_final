# Deploying to a DigitalOcean droplet

One small server runs everything (Caddy for HTTPS, Node for the site and API). The database stays on MongoDB Atlas (free).
The domain `kalpvanayurvedashram.in` is bought at Hostinger and only points at the droplet. No Hostinger hosting is needed.

## Cost
- Droplet Basic Regular, 1 GiB RAM, 1 vCPU, 25 GiB SSD, Bangalore: **$6/mo** (+ $1.20/mo for weekly backups).
- Domain: Hostinger 3-year cart = Rs 1 for year 1, then Rs 899/yr, Rs 1,799 up front plus tax; renews at Rs 899/yr.
- Atlas free.

## Smaller server (512 MiB RAM)
It fits: the build happens on your PC, so the server only runs Node (~100 MB) and Caddy (~30 MB). `remote.sh` adds a 1 GiB swap file
(so `npm ci` cannot be OOM-killed) and caps Node's heap at 192 MB. Any Ubuntu 22.04/24.04 or Debian 12 server with root SSH works, not only DigitalOcean.
Skip the droplet steps below and use your server's IP.

## Database: on the server, or Atlas
At the first deploy, `deploy.sh` asks for an Atlas URI. **Press Enter instead to run MongoDB on the server itself**: no Atlas account, no IP allow-list (skip Atlas steps 1 and 5 below).
`remote.sh` then installs MongoDB 8.0, bound to 127.0.0.1 only, with a password login (`kalpvan_app`, readWrite on `kalpvan_live` only) and a 256 MB cache.
It is tight on 512 MiB (the swap file absorbs the peaks) but fine for low traffic. The data then lives only on this server: turn on your provider's backups or snapshots (or install `mongodb-database-tools` and schedule `mongodump`).

## One-time setup
1. **Atlas** (Security > Database Access): add a new user `kalpvan_app` with an autogenerated password, then delete the old database user.
   Build the URI: Connect > Drivers, copy it, replace `<password>`, and put the database name `kalpvan_live` between the host and the `?`:
   `mongodb+srv://kalpvan_app:PASSWORD@<cluster-host>/kalpvan_live?retryWrites=true&w=majority`
2. **SSH key** (Git Bash): `ssh-keygen -t ed25519` (press Enter 3 times), then `cat ~/.ssh/id_ed25519.pub`.
3. **DigitalOcean**: create the account, then Create > Droplet: Ubuntu 24.04 LTS, Bangalore, Basic > Regular > $6/mo, authentication = SSH Key (paste the public key), tick Backups. Note the droplet IP.
4. **Domain** (Hostinger): buy `kalpvanayurvedashram.in`. Then Domains > the domain > DNS / Nameservers, keep Hostinger's nameservers, and in the DNS records:
   - delete any existing `A` or `CNAME` record for `@` and `www` (Hostinger's parking records);
   - add `A` `@` -> droplet IP and `A` `www` -> droplet IP, TTL 300.
5. **Atlas** > Network Access: add the droplet IP (and remove `0.0.0.0/0` if present).

## Deploy (and every later update)
From Git Bash in this folder:

    bash deploy/deploy.sh <droplet-ip> kalpvanayurvedashram.in

First run: paste the Atlas URI when asked. The script prints the admin login once (it is kept in `/etc/kalpvan.env` on the server).
It builds the site here, uploads it, installs Node and Caddy, loads the 37 treatments into the empty database, and starts the service.
HTTPS appears by itself a few minutes after the DNS records resolve (check with `nslookup kalpvanayurvedashram.in`).

## After the first deploy
- Open https://kalpvanayurvedashram.in/login, sign in as admin, upload the doctor photo.
- Logs: `ssh root@<ip> journalctl -u kalpvan -n 50 --no-pager`
- Admin password again: `ssh root@<ip> grep ADMIN_PASSWORD /etc/kalpvan.env`
- Wrong URI entered? `ssh root@<ip> rm /etc/kalpvan.env`, then re-run deploy.sh.
- The droplet's weekly backup covers the server and uploaded photos. Atlas free has no backups: export bookings from Atlas now and then.
